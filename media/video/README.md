## 压缩结果与边界

- 六个源文件合计119,673,023字节（114.1 MiB），衍生件合计23,350,549字节
  （22.3 MiB），减少80.5%。这些是媒体字节数，不是整个安装包大小。
- 视频：H.264 High@3.1、yuv420p、856×482、30 fps、libx264 slow/CRF21、
  `faststart`。98遍片头原为854×480，等比例缩放/补边到统一画布。
- 音频：原AAC-LC、44.1 kHz、双声道，直接复制压缩数据包；未重新编码、
  未重采样、未裁剪或增加淡化。
- 所有视频帧数与精确时长保持不变；音轨略短于画面末尾的部分视为静音，
  不能将音轨时长用作循环长度。音频数据包哈希核对相同。
- 六个文件均完整解码通过；SSIM为0.990690～0.994101。SSIM是辅助质量指标，
  不等于“无损”或人工确认画质/听感无差异。当前仍需人工验收字幕边缘、片头和接缝。

本次不使用HEVC/AV1来进一步压缩，以避免为素材压缩引入新的解码兼容要求。
没有额外添加“星光播放器”等标题。

## 复现与校验

在仓库根目录，安装好FFmpeg工具的开发机器上执行（用户设备不需要FFmpeg）：

```sh
node tools/video-materials/prepare-bundled.mjs /path/to/素材集合 /path/to/new-output
node scripts/verify-video-assets.mjs
node scripts/verify-video-assets.mjs /path/to/StarlightPlayer.app/video
```

压缩工具要求输出目录不存在，并先验证源文件哈希，防止覆盖原件或误用修改过的素材。
生成 `encoding-evidence.json`，验证帧数、时长、音频包、完整解码和SSIM。
不同FFmpeg/libx264版本可能生成不同字节；重新编码后必须重测、更新清单/版本，
不能因为肉眼时长一样就沿用旧哈希。校验工具只核对清单/文件完整性，不替代完整解码。

iOS以folder reference将本目录放在bundle的`video/`；Android通过
`sourceSets.main.assets`将其放在`assets/video/`。不依赖本机绝对路径或在线URL。
桌面正式安装包尚未接入这套视频任务和资源。

变更媒体时必须同时更新revision、SHA-256、字节数、精确时长及测试记录，并重建双端。
旧revision的运行中快照将被拒绝恢复，避免按旧时间轴播放新素材。
素材授权/发行许可需要维护者另行确认，技术压缩验证不代表版权审核。

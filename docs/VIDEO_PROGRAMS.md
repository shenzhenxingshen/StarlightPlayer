# 可编辑的定时视频流程（开发分支）

2026-11-19：接入移动端iOS/Android工程，尚未发布。电脑版仍是音频正式功能加独立
视频原型，不能将本说明理解为电脑版已支持。验证范围见
[本次执行记录](test-runs/2026-11-19-video-program-integration.md)。

## 使用方式

1. 普通模式进入“任务”，同页分为“音频任务”和“视频任务”；关怀模式仍隐藏任务tab。
2. 系统提供49遍、98遍两套默认流程，初始关闭，避免升级后意外播放。
3. 点击任务信息编辑名称、时分秒循环拨轮、星期重复、视频序列、各项重复次数；
   可添加、移除、上移、下移片段，并保存或删除任务。编辑页即时显示正文总遍数、
   素材条目数、总时长和约结束时刻；片段可折叠，避免长流程占满屏幕。
4. 开关只控制自动加入。手动“加入”不受开关限制，但必须处于选定星期对应的
   `[启动时刻, 启动时刻+总时长)`内。没有“现在开始从片头另播一套”的隐式行为。
5. 视频取代播放页唱片区域，保留素材比例；支持进入/退出全屏和手机横屏自动全屏。
   显示公共流程进度、当前片段及片段重复序号。
   “暂停视频”只暂停本机，“追平并继续”加入当前公共位置。
6. “返回音频播放”停止视频、恢复原音频控制；不会把跳过的视频遍数记入音频统计。

默认49遍：
`49遍片头×1 → 礼敬诸佛×1 → 可重复多次的一遍×48 → 最后一遍×1 → 片尾×1`。

默认98遍：
`98遍片头×1 → 礼敬诸佛×1 → 可重复多次的一遍×97 → 最后一遍×1 → 片尾×1`。

六份素材共用，详见[资产台账](../media/video/README.md)。

## 播放与任务界面

- **拨轮**：音频和视频任务共用三列循环拨轮，23→00、59→00以及反向滚动均可，
  各列独立不进位。实现为五份重复数据、停止后无动画回中，而非无限原生数据源。
  大字体增大行高；读屏通过增加/减少操作循环选值。滚动期间锁住外层页面，防止误滚。
- **任务卡片**：按启动时刻排序，展示星期、正文遍数、整套时长、进行中/下次窗口和
  自动启动状态。窗外“加入”不可用；正在播放时“查看播放”只导航，不重新加载。
  同任务已加入的快照优先于后来编辑的配置。
- **遍数**：进度条上方为公共流程正在进行的正文遍数，下方为正文总遍数。
  49遍=普通正文48遍+最后一遍1遍，片头、礼敬和片尾不算正文遍数。
  非正文阶段显示片段名称，不把片头当第1遍。数字使用千分位。
- **时间**：整套进度条不可拖动，两侧显示整套已过/总时长；当前片段的内部耗时和
  该条目重复序号单独显示。暂停后公共时间仍推进，恢复时追平，不冒充本机完成量。
- **布局**：手机竖屏使用视频、进度和操作的纵向布局；手机横屏自动全屏。
  可用宽度≥850、高度≥600且字体倍率<1.6时，右侧显示流程列表；小窗口/大字体
  切为上下结构。按窗口而非设备名称判断，适用于iPad分屏。
- **全屏常驻进度**：在视频原遍数区域（左下、底部字幕上方）全程显示`2/49`，
  不随控制栏自动隐藏；片头、礼敬和片尾显示阶段名，终点显示“已结束”。
  位置跟随实际视频内容缩放并计算黑边偏移，不锚定屏幕边缘；使用白字和小面积
  半透明底色。显示公共流程位置，不是本机完成次数，暂停后仍按公共时钟更新。
- **全屏控制**：隐藏标签栏；退出、暂停/追平置于顶部，完整时间条置于底部，
  不再重复显示大号遍数。实际播放时约3秒隐藏这些控制，点击画面重新显示，
  但常驻遍数始终保留。暂停、出错、忙碌和读屏开启时保持控制。Android返回键先退出
  全屏。退出后恢复普通布局；非播放标签旋转不会误开全屏。
- **无重载**：全屏只调整同一个原生视频表面的尺寸，不创建第二个播放器、不发
  load/seek/pause。全屏尺寸取安全区内实际视口，避免视频比例推导出屏幕外的控件。

## 必须保持的业务规则

- **整套时间轴**：`elapsed = 当前设备时间 − 本次计划启动时间`。不是原音频模式的
  “当地午夜对单曲时长取模”。同一配置、素材revision、日期、时区和校准后的设备时间
  才有相同目标进度；没有服务器授时，不能承诺跨设备输出采样级同步。
- **迟到/恢复**：从当前所属片段的内部位置加入，不补播开头，不凑足本机49/98遍。
  公共“第几段/第几遍”不是用户实际完成遍数。
- **不循环**：终点为开区间，达到终点后停止；不会回片头，也不继续补遍数。
- **快照**：已加入的本次流程冻结任务配置、起点、终点、素材revision。编辑或删除任务
  不改变当前会话；用户主动返回音频后，该会话停止。编辑影响后续新实例。
- **日历**：星期按计划开始的本地日期判断，跨午夜仍属于前一天；搜索今天和昨天的
  有效窗口，不按固定24小时倒推日期。夏令时不存在的本地时刻跳过，回拨时重复时刻
  采用JavaScript Date选择的第一次；罕见的23小时日期中重叠实例取较新一次。
- **冲突**：同一天同一秒不允许同时启用音频/视频两个任务。视频窗口重叠时取较新
  起点，处理过较新任务后不自动回退较旧任务；显式暂停也不会被轮询取消。
  后启动音频任务会抑制当时仍在窗口内的旧视频任务；旧音频延迟通知不抢占较新视频。
  这不是待播队列，多个日程覆盖时建议用户错开时段。
- **原音频不变量**仍是每首N个有效周期后执行四种模式，同步阈值和计数算法未改。
  切入视频会暂停音频、撤销未完成音频周期资格，但保留音频累计值。

## 边界与限制

视频目前**仅前台播放**。Android后台到点发提醒，不强行打开Activity或由Headless
启动无画面视频；iOS被挂起/杀死时依赖系统通知让用户返回加入。前台轮询可发现仍在
整套窗口内的任务，视频不套用音频的15分钟延迟上限。通知仍受系统权限和调度影响。

名称1～30个Unicode字符；至少选一天；1～100个序列条目；单项1～1,000次；
展开后最多1,000段、总长小于24小时。限制是原生组合规模的保护，不改变音频遍数上限。
尚不提供任意外部视频导入、自由拖动公共时间轴、画中画或后台视频音轨播放。

原生加载/seek有准备耗时，可能在非常靠近流程终点时拒绝加入。长时间卡顿、系统授时
跳变和声卡输出延迟仍需真机验证；当前播放器时钟对齐不等于听觉输出零延迟。

| 位置                                                                        | 职责                                          |
| --------------------------------------------------------------------------- | --------------------------------------------- |
| `packages/program-core/src/index.ts`                                        | 整数tick编译、二分定位、半开边界；不依赖RN    |
| `packages/program-core/src/tasks.ts`                                        | 任务验证、默认流程、日历、不可变会话快照      |
| `src/video/catalog.ts`、`media/video/manifest.json`                         | 同一素材清单与revision                        |
| `src/video/TaskScreens.tsx`、`taskStore.ts`                                 | 列表、编辑、星期、排序、重复及调度同步        |
| `src/video/runtime.ts`、`ownership.ts`                                      | 生命周期、命令串行化、音频/视频互斥与去重     |
| `src/video/Player.tsx`                                                      | 原生画面、公共流程状态及控制                  |
| `src/video/presentation.ts`                                               | 公共进度视图模型、任务窗口、临时全屏状态      |
| `src/components/TaskTimePicker.tsx`                                        | 音频/视频共用的循环时分秒拨轮                |
| `src/services/scheduledTask*`                                               | 原有系统日程桥接，合并两类任务                |
| `ios/StarlightPlayer/VideoProgramPlayer.mm`                                 | AVMutableComposition、AVPlayer、AVPlayerLayer |
| `android/app/src/main/java/com/starlightplayer/VideoProgramPlayerModule.kt` | ExoPlayer裁剪播放列表、TextureView、音频焦点  |

iOS将多段拼成原生组合，Android将相同文件引用展开为原生裁剪播放列表。普通片段
切换不经过JS的QueueEnded→重载循环，避免每遍都由JS重新启动。首次加入/恢复按
墙钟预留约350ms准备，iOS使用host clock约定启动；Android等待READY后按目标时刻
启动。2026-11-19起改用**片段边界同步**：

- 任务启动、加入或恢复时，按原任务起点追平。
- 每个片段自然开始（包括同一文件的下一遍），比较播放器位置与公共时间轴。
  绝对偏差不超过250ms时直接连续播放；超过才暂停并有界重新对齐。
- Android以原生播放列表自动切换事件触发，iOS以组合时间轴边界事件触发。
  使用展开后的片段序号去重；seek产生的切换不是新边界，向后纠偏再次跨过同一
  边界也不重复处理，向前跳过的片段不补播。
- 每500ms的检查只保留任务窗口截止保护，**不在片段中途seek**。
  短暂卡顿或系统时钟变化产生的偏差等下一片段开始再校准；暂停后手动恢复仍
  立即追平，不沿用暂停位置。等待/纠偏期间的取消使旧回调失效。
- 重新对齐整体有6秒上限，准备最多尝试4次。iOS另对不返回的preroll回调设置
  600ms单次等待上限并有限重试，避免向后跨素材接缝时一直准备。
  Android首次预留350ms，准备过慢时后续尝试依次预留700/1050/1400ms，
  避免设备始终赶不上相同的350ms目标；重试仍按原任务墙钟计算目标位置。

取舍：不再承诺片段播放期间一直在250ms以内；严重卡顿可能持续落后至下一个片段，
但任务仍按原窗口结束（停止检查存在轮询和调度延迟）。这套设计不等于声学无缝
承诺；与A05音频的RNTP链路相互独立，本次未改音频计数、媒体编码或播放器缓冲参数。

“我的→导出诊断日志”合并JS日志与最近300条原生视频事件，包含加载、边界比较、
纠偏、准备重试和错误；Android另记录播放状态变化。原生行使用Unix毫秒时间，
便于定位是否反复seek。该缓冲为进程内记录，杀进程后不保留；旧安装包不支持时
仍可导出原有JS日志。

所有跨引擎操作共用现有`enqueuePlayerCommand`及原生进程锁。视频持有播放权时
旧RNTP结束、远程控制和自动恢复事件不应重启音频。切回音频恢复锁屏能力。
原生加载有有界等待/取消；后台、来电及耳机断开会暂停视频，需追平后继续。

## 本地存储

以下使用现有默认MMKV实例，不迁移或重命名原音频key：

| key                    | 内容                                       | 恢复/失败策略                                        |
| ---------------------- | ------------------------------------------ | ---------------------------------------------------- |
| `video_tasks_v1`       | `VideoTask[]`                              | 缺失时返回关闭的默认任务；损坏保留原值，忽略无效条目 |
| `video_session_v1`     | occurrence快照、playing/paused/stopped意图 | 校验文件/时长/revision；不兼容拒绝恢复               |
| `video_occurrences_v1` | 最近100个已处理的`taskId@startEpochMs`     | 防止1秒轮询重复加入/失败无限重试                     |
| `media_owner_v1`       | audio/video                                | 视频快照无效时解除占用，恢复音频控制                 |

会话恢复使用快照而非最新编辑表；“playing”前台重入时追平，“paused”不自动播放。
原生系统中断不改变公共流程；界面依据原生状态提供恢复按钮。

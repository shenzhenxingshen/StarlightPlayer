# 版本发布记录

本目录保存“某个版本实际构建、测试、分发和回滚到了什么状态”的小型、脱敏索引。构建方法见 [`../RELEASE.md`](../RELEASE.md)，详细测试结果必须链接 [`../test-runs/`](../test-runs/README.md)。

## 记录规则

- 推荐每个营销版本一个主记录；同一版本有多轮发布时在文件中按平台 build 分节，或拆成 `vX.Y.Z-buildN.md`。
- 发布前从 [`TEMPLATE.md`](TEMPLATE.md) 创建记录并标为 `DRAFT`；完成发布决定后改为 `FINAL`。
- commit、构建号、制品哈希或签名发生变化，必须新增候选条目和测试记录，不能沿用旧结论。
- 安装包、Archive、完整日志、截图和商店导出放在受控制品系统；Git 只记录哈希、受控 URI、状态和责任人。
- 不记录密码、私钥、Provisioning Profile、keystore、个人账号、UDID 或未经脱敏的用户诊断。
- `FINAL` 后不得改写历史状态；纠错在末尾追加更正，新的发布/复测建立新记录。

## 状态

| 状态          | 含义                                                 |
| ------------- | ---------------------------------------------------- |
| DRAFT         | 正在构建、测试或等待外部平台处理，不能作为已发布证明 |
| FINAL         | 发布决定与渠道结果已经核实，记录字段完整             |
| SUPERSEDED    | 已被更高 build 或补丁版本取代，保留历史              |
| RECONSTRUCTED | 根据现有文件和日志事后恢复，缺失项必须保持 `UNKNOWN` |

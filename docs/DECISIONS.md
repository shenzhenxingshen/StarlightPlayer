# 关键设计决策记录

> 文档类型：长期规范。下列决策根据现有源码和历史行为于 2026-10-16 补录；原始决定日期无法从仓库可靠恢复。改变任何已接受决策前，必须更新本页、对应架构文档和测试。

## D-001：每首 N 遍优先于四种播放模式

- 状态：已接受。
- 决策：先完成当前曲目的 N 个有效完整周期，再执行单曲播放、单曲循环、列表播放或列表循环。
- 原因：重复遍数是功课任务的一部分，不是播放器的普通 Repeat 设置。
- 后果：所有结尾处理必须先计数再决策；UI、后台 Service 和恢复路径不能各自实现不同规则。
- 详细规范：[PLAYBACK_ARCHITECTURE.md](PLAYBACK_ARCHITECTURE.md)。

## D-002：RNTP 始终使用单曲队列，RepeatMode 为 Off

- 状态：已接受。
- 决策：原生队列只装当前曲目，不构造两份曲目或列表循环队列；重播、换曲和停止由 JS 状态机处理。
- 原因：原生 RepeatMode 无法表达 N 遍优先、同步逐遍对齐和两套计数。
- 后果：`PlaybackQueueEnded` 是关键业务事件；任何改为原生循环的方案都必须重新证明计数、同步和恢复不变量。

## D-003：同步位置使用设备本地当天时间取模

- 状态：已接受，跨时区产品口径仍待确认。
- 决策：`(当前时刻 - 设备本地当天 00:00) % 曲目时长` 得到对齐位置，不依赖服务器。
- 原因：离线、多设备在时间准确且时区一致时可计算相同位置。
- 后果：设备时钟、时区和输出链路延迟会影响听感；不能宣称采样级同步，也不能把同步模式固定 `seekTo(0)`。

## D-004：模式计数、任务累计和周期资格分离

- 状态：已接受。
- 决策：`session_count` 决定何时执行播放模式；`playback_task_progress.completedCount` 用于跨重启累计展示；`cycle_eligible` 决定当前周期到尾时是否可计数。
- 原因：单曲循环达到 N 后需要重置模式窗口，但用户累计遍数仍应连续；中途 seek/同步加入又必须使当前尾段失去资格。
- 后果：三者不能合并或互相覆盖；真换曲/新任务与后台恢复必须采用不同清零策略。

## D-005：所有影响队列或播放状态的 TrackPlayer 写命令串行化

- 状态：已接受。
- 决策：UI 和 PlaybackService 中影响队列或播放状态的写命令都通过 `enqueuePlayerCommand`，同时由 Android/iOS `PlayerCommandLock` 防御桥接重入；hooks、事件注册和只读查询不受此表述约束。
- 原因：播放、换曲、QueueEnded、远程控制和 watchdog 可能并发到达；无序命令会串曲、重复计数或覆盖播放意图。
- 后果：业务代码不得直接新增绕过队列的 TrackPlayer 写命令；锁超时、租约和释放必须保留失败日志。

## D-006：用 pending token、generation 和 active ID 识别真换曲

- 状态：已接受。
- 决策：换曲前写入 pending change 并递增 generation。ActiveTrackChanged 核对事件采样的 MMKV generation、pending/current track 和原生 active ID；QueueEnded 还会在 metadata 存在时附加核对 `starlightGeneration`。
- 原因：旧 `last_track_id` 方案会把真换曲误认为后台恢复，也无法拒绝迟到事件。
- 后果：恢复同一原生队列保留计数；迟到的 ActiveTrackChanged/QueueEnded 不得污染新曲。

## D-007：一个安装包按窗口比例响应式布局

- 状态：已接受。
- 决策：高度/宽度 `>1` 为竖屏、`0.75～1` 为方屏、`<0.75` 为宽横屏；iOS 为 iPhone/iPad Universal。
- 原因：手机、平板、分屏和电视尺寸应由当前窗口决定，不应按设备型号构建多个包。
- 后果：旋转和窗口变化只能重排 UI，不能初始化播放器、seek、换曲或清零计数。

## D-008：业务数据默认只保存在本机

- 状态：已接受。
- 决策：设置、播放任务、统计和诊断使用 MMKV；音频内置；当前没有业务后端、账号、广告或分析服务。
- 原因：产品需要离线使用并减少账号、网络和隐私依赖。
- 后果：卸载会删除本地数据；多设备只同步播放位置而不云同步累计遍数；新增网络能力必须同步隐私、权限和安全审计。

## D-009：诊断信息导出为原生文件

- 状态：已接受。
- 决策：Android/iOS 原生模块生成 UTF-8 `.txt` 并交给系统分享面板，不依赖长文本复制。
- 原因：剪贴板可能截断大量日志或造成“复制成功”的误判。
- 后果：导出失败必须有日志和错误反馈；文件只有在用户主动选择分享目标后才离开设备。

## D-010：关怀模式通过减少能力降低误操作

- 状态：已接受，但不等同完整无障碍。
- 决策：控制按钮只保留放大的播放/暂停，隐藏高风险设置和列表，并收紧远程 seek capability。
- 原因：关怀模式首先解决操作复杂和误触，不是另一套播放器业务规则。
- 后果：既有曲目、模式、重复数和同步设置仍保留；无障碍语义、大字体、焦点和 Reduce Motion 需要独立建设。

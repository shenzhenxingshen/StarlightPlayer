# 桌面端技术预览

状态：2026-11-15，`codex/desktop-mvp`，桌面版本 `0.1.0`。这是电脑版测试预览，不是手机版 `1.1.1` 的新发布包。离线安装包构建见[打包与安装](PACKAGING.md)，具体通过情况以测试记录和 CI 结果为准。

拿到安装包后的操作见[安装与试用指引](INSTALL.md)；无需按开发章节安装工具链。

## 1. 产品边界

桌面端以手机版为功能与视觉基准。N 个有效周期优先于四种播放模式、按本地当天零点对齐同步位置，这两项规则不变。业务定义以[播放架构与状态机](../PLAYBACK_ARCHITECTURE.md)为准。

本阶段没有移动手机工程，没有改动 RNTP、iOS/Android 工程、音频文件或最低系统版本。尤其没有因桌面开发提高 iOS 13/14 的兼容门槛；原有最低系统与最终制品的核验要求仍适用。

### 与手机版的对应关系

| 功能 | 当前桌面实现 | 验证范围 / 仍需验收 |
| --- | --- | --- |
| 配色与导航 | 直接引用手机颜色；播放、列表、任务、我的四入口 | Chromium 自动化；真实 WebView/读屏待验收 |
| 离线曲库 | 手机同一份 21 首资产、分类和标题；A05 为现有 WAV | 清单与哈希验证；没有另行转码 |
| 播放 | 播放/暂停、上下首、列表选曲、四种模式，N 个有效周期优先 | 纯逻辑、手机契约、真实 libmpv null-output 测试 |
| 重复遍数 | 1/108/1,000/10,000 快捷值、正安全整数、千分位、5,000,000 输入 | 大数、溢出、无效输入和草稿保留测试 |
| 当前遍数 | N>1 显示两数；N=1 单曲循环只显示当前数；其余隐藏；无汉字前缀 | UI/核心测试 |
| 同步 | 本地当天零点取模；每遍和恢复时重对齐；0～1,500ms 可取得计数资格；禁用界面/远程 seek | 规则和命令已验证；真实声音/多设备待测 |
| 持久化 | 曲目、配置、完成数和每日曲目统计；重开不自动播，继续计数 | 核心与原生重启测试 |
| 任务管理 | 3 个默认任务、排序、增删改、启停、秒级时间、4 项播放配置、立即播放 | UI 与真实原生任务测试 |
| 后台任务 | 原生宿主调度；窗口隐藏/最小化不依赖 WebView 计时器 | 无 WebView 定时触发已测；实际系统睡眠/隐藏长测待测 |
| 关怀 | 持久化开关、隐藏任务/计数/遍数设置/诊断、放大按钮、禁用拖动、限制远程控制 | UI 与原生命令权限测试 |
| 响应式 | 竖屏五按钮横排；方/宽屏三栏、数字在进度左侧 | 5 种尺寸几何与交互测试；跨系统字体/高 DPI 待测 |
| 诊断 | 最近 30 条、完整文本导出并定位文件、运行期日志轮换 | UI mock 导出及真实文件内容/轮换测试 |
| 异常恢复 | 进度停滞检测、1.5/3/6 秒重试；用户暂停/停止优先 | 原生故障注入测试；物理拔设备/系统中断待测 |
| 桌面系统适配 | 托盘、默认关闭留后台（可取消）、系统媒体中心事件适配 | 各平台编译/包内解码验证见安装包记录；OS 媒体键、托盘菜单实际操作仍待测 |

首次无保存数据时：第一首 A01、重复 1 遍、单曲循环、同步开启、关怀关闭，不自动播放。有已保存配置时不会覆盖为默认值。

手动重新选曲（包括重选本曲）、上下首以及完成后再次播放会创建新播放任务；修改重复遍数、模式、同步开关不会清零或重新载入曲目。暂停时修改配置不自动播放。调低 N 在下一次自然结束判断，不中途强行停止。

数字上限是 JavaScript 安全整数 `9,007,199,254,740,991`，不是任意精度无限整数；5,000,000 可用，也不会生成对应数量的播放队列项。

### 任务与手机版 v1.1 的对齐规则

默认值直接复用手机 `src/constants/scheduledTasks.ts`，首次创建均为**关闭定时**：

| 任务 | 时间 | 曲目 | 遍数 | 模式 | 同步 |
| --- | --- | --- | --- | --- | --- |
| 早自习 | 05:30:00 | A05 | 49 | 单曲播放 | 开 |
| 见缝插针 | 06:30:00 | A05 | 500 | 单曲循环 | 开 |
| 晚自习 | 20:00:00 | A05 | 98 | 单曲播放 | 开 |

- 列表只显示三行：启动时间；名称和遍数；模式和同步。不显示歌曲名。
- 新任务默认 08:00:00、A05、1 遍、单曲播放、同步、关闭定时；名称须填写，去首尾空格后 1～30 个 UTF-16 单元。启用的任务不能使用相同启动时刻。
- 保存不开始播放，修改保持原启用状态；删除不停止已经开始的播放。所有默认任务都删除后，下次启动保持空列表。
- “立即播放”无视启用开关和启动时间，一次应用曲目、遍数、模式、同步四项配置，并创建新的计数任务；不改变关怀设置。
- 同步任务对齐本地当天零点时间轴；非同步任务从实际执行时刻的 0ms 开始，不追赶已迟到的进度。
- 关怀模式只隐藏任务入口，**已经启用的任务继续有效**。
- 桌面新增保护：最多保存 1,000 个任务，稳定 ID 及输入校验；这是技术限制，不是手机已有产品规则。重复遍数仍支持 500 万及更大的安全整数。

### 后台、恢复与定时边界

- 原生宿主每约 250ms 检查到期任务，不依赖前端轮询。首次使用默认勾选“关闭窗口后留在后台”；关闭窗口后播放和定时任务继续，托盘可再次打开或彻底退出。“我的”可取消勾选，此时关闭窗口即退出。升级保留已保存的选择，不强制覆盖旧设置。
- 桌面图标由手机原图生成独立的圆角透明衍生资源，供应用和托盘使用；不修改手机图标。运行中的进程需彻底退出并重新打开新版，才会加载新的图标。
- 不主动唤醒睡眠中的电脑，不提供开机自启。彻底退出/关机期间无法执行；**冷启动不追补**退出期间的任务。
- 同一运行进程恢复后，计划时刻不超过 15 分钟的任务可补执行，超过则跳过；多个到期任务按时间顺序启动，最后一个生效。
- 新增、启用或修改启动时间不会追补操作之前的计划时刻。手动播放不受 15 分钟窗口限制。
- 自动执行先持久化 `任务 ID + 本地日期 + HH:mm:ss` 认领记录，再播放。保留 8 天去重数据；采用 **at-most-once**：认领后若进程崩溃或启动失败，该次任务可能漏播，但不会反复启动。不能承诺 exactly-once。
- 时钟跳变、跨午夜或事件循环长时间停顿会使当前周期资格失效；正在同步播放时重新加载并对齐，暂停状态不会自动恢复。DST 重复时刻选择第一次，不存在的时刻跳过；实际 DST/时区切换尚需系统测试。
- 预期播放但进度 20 秒无推进时触发恢复；最多 3 次延迟 1.5/3/6 秒重试，健康推进 10 秒后重置预算。用户暂停/停止取消待重试；耗尽后提示手动重试。同步重试仍按同步规则重新判断资格，不无条件计数。

托盘与系统媒体事件都走原生宿主同一个串行入口。关怀模式只接受播放/暂停；普通模式允许上下首和停止；仅普通、非同步模式允许远程 seek。macOS 额外禁用系统前后曲/seek 能力；其他系统目前仅在宿主拒绝，不承诺按钮被隐藏。当前 `souvlaki` macOS 后端没有注册系统 `stopCommand`，停止可用托盘，不能宣称控制中心停止键已支持。

## 2. 架构与代码位置

```text
apps/desktop/src/                 React 界面、手机版视觉引用
         │ snapshot / control
apps/desktop/src-tauri/src/host.rs 单线程原生播放宿主，串行处理命令与引擎事件
         ├── core.rs → QuickJS → packages/playback-core/src/index.ts
         │                       └── tasks.ts（任务纯规则，引用手机定义）
         ├── engine.rs → libmpv 客户端 API 2.x
         ├── schedule.rs（本地时区/日历适配）
         ├── shell.rs（托盘/媒体中心，不负责播放业务决策）
         └── JSON 状态文件、JSONL 事件记录
```

桌面端纯 TypeScript 状态机不依赖 React、RNTP、系统时钟或存储。Rust 宿主把当前时刻、当地零点、引擎事件传入 QuickJS，执行状态转换和副作用。WebView 仅展示快照、提交操作；窗口隐藏或渲染计时器变慢，不应成为计数驱动。

**手机版尚未迁移到 `packages/playback-core`。** 当前是“抽出可共享核心，并用一致性测试约束”的过渡阶段，不能宣称两端已经运行同一套完整状态机。`__tests__/utils/desktopContractParity.spec.ts` 对比两端四模式决策、N 边界、结束位置容差与同步取模规则。

新增工程独立管理依赖和 lockfile。根目录仍是 React Native 工程，不要求先整体改造为 workspaces。根 `tsconfig.json` 排除桌面工程，桌面自行做类型检查。

### 音频和引擎边界

- `scripts/prepare.mjs` 从手机版曲目表生成 21 首曲目的桌面清单和 SHA-256，并打包纯 TS 核心、生成桌面图标衍生文件。只写桌面 `generated/`。
- 开发模式读取源码中的 `ios/StarlightPlayer/audio`；离线包原样复制这 21 首音频，其中 A05 为 WAV，其余为 MP3，不转码或改变时长。
- release 模式只加载应用资源目录 `runtime/audio` 与 `runtime/lib`，缺失时明确报错，不回退到源码或 Homebrew。全部资产继续校验 SHA-256。
- 原生宿主按曲目 ID 白名单解析文件并校验哈希，不接受 UI 传入任意路径。
- 当前是**单条原生队列在 EOF 后重新加载**，不是预加载双曲连续队列。`gapless-audio` 选项不能单独证明换遍无缝或不会吞音。
- `started` 代表 seek/play 指令返回；`native-playback-restart` 是引擎事件。二者都不是扬声器实际出声时刻。
- EOF 附带的进度来自近期采样，不可将其当作精确文件长度或硬件播放结束位置。

## 3. 开发和运行

本轮实际验证环境：macOS 27.0.1 Apple Silicon，Node 25.6、npm 11.8、Rust 1.100、libmpv 0.42/API 2.x。桌面锁文件固定 Tauri JS 2.12.4、Rust 2.12.5、React 18.3.1、Vite 8.3.8、QuickJS 封装 rquickjs 0.14。

这些是测试环境，不代表已经验证的最低版本。根移动端依赖和部署目标保持不变。

开发机需要 Node/npm、Rust/Cargo、平台构建工具和可加载的 libmpv。macOS 使用 Xcode 命令行工具；Windows 和 Linux 的原生工具链由 `.github/workflows/desktop-build.yml` 配置。各平台实际构建结果见[离线安装包记录](../test-runs/2026-11-15-desktop-offline-installers.md)。这些是开发机要求，安装测试包的用户不需要 Node、Rust 或另行下载音频和 libmpv。

```bash
# 仓库根目录
cd apps/desktop
npm ci
npm run dev
```

开发模式自动生成核心和资源清单。libmpv 默认只查找 macOS Homebrew 两个固定目录；其他路径通过开发者环境变量 `STARLIGHT_LIBMPV` 指定绝对动态库路径。该变量是受信任的本机开发配置，不对用户界面开放。

```bash
STARLIGHT_LIBMPV=/absolute/path/to/libmpv.2.dylib npm run dev
```

`npm run web:dev` 只提供本地 UI 服务，不包含音频引擎；直接用浏览器打开时显示无法连接播放服务是预期行为，不能以此评估原生播放。

### 离线安装包构建

在 `apps/desktop` 中运行：

```bash
npm run bundle:prepare
npm exec tauri -- build --config generated/bundle.config.json \
  --bundles dmg --no-sign
```

macOS 输出：`src-tauri/target/release/bundle/dmg/*.dmg` 和同级 `macos/*.app`。Windows 使用 `--bundles nsis`；Linux 使用 `--bundles appimage`。这些命令需在各自平台及完整构建环境执行。

新打包脚本封装音频、libmpv 和传递依赖，Windows 额外嵌入离线 WebView2 安装程序；不是只封装主可执行文件。macOS 暂时提供 ARM64 / x64 两包，不冒充 Universal。尚无 Developer ID 公证或 Windows 发行签名，操作系统可能提示未验证开发者。具体兼容基线和验证步骤见[打包与安装](PACKAGING.md)。

重新构建不会热更新正在运行的旧原生实例。需保存工作并正常退出旧实例后重新打开；不要同时用两个实例写同一个播放数据目录。

## 4. 数据与安全

macOS 预览数据位于用户应用支持目录下的 `org.starlightplayer.desktop.preview`：

- `playback-v1.json`：配置、sessionCount、completedCount、dailyStats 等。
- `desktop-v1.json`：任务、自动执行去重、启用时间屏障、关怀/关闭留后台偏好。两个 JSON 均用临时文件写入、同步后替换；单个读取上限 4 MiB。
- `playback.lock`：进程独占锁，避免两个宿主并发写入。
- `playback.jsonl`：原生事件、墙钟/单调时钟、代次、同步目标与进度。
- `playback.previous.jsonl`：当前日志达到约 20 MiB 时在运行期间轮换，保留最近一份旧日志；新一轮会覆盖更老的 previous。
- `exports/`：用户手动导出的诊断 `.txt`，包含版本、系统、状态、任务、偏好及当前/上一份事件日志。不会自动上传或自动删除；用户可以自行清理。
- 关怀模式以原生偏好为准；首次支持从旧预览 WebView 的 `starlight.desktop.care.v1` 做一次迁移，不作为后续权威数据。

坏状态文件保留供诊断，初始化会报错，不静默清除用户计数。冷启动恢复配置和计数，但不会继承上一进程尚未完成周期的资格。

原生接口只允许主窗口的 `snapshot/control`；拒绝伪造内部 EOF/远程事件、未知字段、任意媒体/导出路径。命令限制 4 KiB、队列容量 32；曲目/数字/任务/配置再次由核心验证。用户输入不拼接成 JS 源码或 shell 命令；任务名称按文本显示。QuickJS 使用内存/栈限制；libmpv 禁止加载用户配置与脚本；窗口采用 CSP。

诊断含任务名称、本地路径及播放习惯，转发前应检查隐私。导出固定到应用目录下，不接受 UI 指定任意写入目标。当前导出和日志轮换在 actor 上同步执行，最大约 40 MiB 的日志复制可能短暂阻塞播放事件/任务处理，尚待性能优化。4 MiB 状态读取上限和长期累计每日统计仍需配套保留/归档策略。

进度 watchdog 能发现“引擎仍返回但没有推进”，**不能中止阻塞在 FFI 调用里的原生死锁**。其他待加固项包括持久化损坏的用户恢复流程、断电耐久测试、跨平台动态库可信分发。

## 5. 测试入口

```bash
# 仓库根目录：保持移动端回归和共享契约测试
npm test -- --runInBand
npm run typecheck:app

# apps/desktop：纯核心、桌面类型与构建
npm test
npm run build
npm run test:native

# apps/desktop：需要本机 libmpv，实时运行但不向扬声器输出
cargo test --manifest-path src-tauri/Cargo.toml --no-default-features \
  --test host_contract native_ -- --ignored --nocapture

# 恢复、用户取消、日志轮换：注入时间/故障，不必真实等待 20 秒
cargo test --manifest-path src-tauri/Cargo.toml --no-default-features \
  --lib native_actor_recovery_and_log_rotation -- --ignored --nocapture

# A04/A05 同时各完成 21 个有效周期；约 25 分钟
STARLIGHT_TEST_CYCLES=21 cargo test --manifest-path src-tauri/Cargo.toml \
  --no-default-features --test host_contract live_ -- --ignored --nocapture
```

直接运行 cargo 前，先执行 `npm run prepare:runtime`。默认 live 测试每首 3 遍，可选 1～21 遍；测试使用各自独立的 `test-results/`，不改正常应用计数。

UI 自动化脚本为 `apps/desktop/scripts/ui-smoke.cjs`。先启动桌面 `npm run web:dev`，在仓库根目录用已安装的 `playwright-cli`：

```bash
playwright-cli --session starlight-desktop open http://127.0.0.1:1420
playwright-cli --session starlight-desktop run-code \
  --filename apps/desktop/scripts/ui-smoke.cjs
```

脚本是 CLI 可执行函数表达式，不是 Jest 测试文件；不要给末尾追加分号。它注入 mock IPC，验证布局、配色、数字输入、模式、关怀、拖动提交、任务增删改/立即播放、恢复取消与诊断导出交互，**不证明 Tauri WebView 或原生音频行为**。截图写入忽略的 `output/playwright/`。

开发阶段执行摘要见 [2026-11-15 桌面测试记录](../test-runs/2026-11-15-desktop-preview.md)；绑定提交和制品哈希的打包验证见[离线安装包记录](../test-runs/2026-11-15-desktop-offline-installers.md)。本阶段没有完整桌面覆盖率报告，不声称全分支覆盖或所有边界通过。

## 6. 后续顺序与验收门槛

1. **真实音频验证**：A04/A05 声卡回环，记录实际声音起点/缺失量；覆盖最小化、CPU 压力、蓝牙、睡眠与唤醒。明确时钟跳变策略后做跨手机/桌面的同步对照。
2. **核心一致性扩展**：记录手机真实事件轨迹并在两套实现回放，尤其系统中断/输出切换/恢复策略。迁移移动端到共享核心另开小步骤，不直接替换已发布服务。
3. **任务与桌面生命周期验收**：实际睡眠/唤醒、系统时间/时区变化、退出后重开、隐藏窗口定时，以及持久化失败和认领后崩溃恢复。

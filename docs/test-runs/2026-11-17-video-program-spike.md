## 2. 验证的问题与技术实现

目标：将四份素材组成一个不可分割的播放流程，以同一发生实例的起点
`startEpochMs` 为零点；迟到或主动恢复时进入该流程当前的位置。

```text
已解析的发生实例起点 + now + 素材 revision
                     ↓
       纯 TS：整数 ticks 时间轴和区间定位
                     ↓
         原生 AVMutableComposition
       片头 → 正文 ×48 → 特殊末遍 → 片尾
                     ↓
                单个 AVPlayerItem
```

- 时间轴按 44,100 ticks/秒构建，半开区间 `[start,end)`；精确边界归下一段。
- Swift 用 JavaScriptCore 执行同一 TS 编译结果的编译和定位函数，不另写第二套定位算法。
- Swift 保留实验性的播放意图、generation 和原生控制；TS `decide` 的纯函数测试不等于
  全平台生产状态机已经抽取完毕。
- 首次加入 / 恢复：精确 seek → preroll → 预约原生 host clock 启播。
- 已知未来起点提前准备，目标为 0；迟到使用默认 350 ms 准备窗口。
- 内部片段衔接交给原生组合媒体，不逐遍等 `QueueEnded`，不逐遍重新 seek。
- 显式暂停、停止使旧异步操作失效；暂停期间不由轮询重新拉起。
- 整体结束不取模重开。流程遍次只表示节目位置，不计作本机完成遍数。
- 没有输出一条新长视频；组合媒体引用四个文件。原型额外打包原视频仅为 A/B 对照。

## 4. 断言方法

每轮保存原始 JSONL、构建身份、完成标记和独立分析。完成标记不等于测试通过；
runner 必须等 `analyze.mjs` 的断言全部通过才返回成功。

- 每个边界前后 0.7 秒检查媒体进度、显示层就绪、视频输出和音频时间戳。
- 稳态媒体时间相对目标墙钟偏差预算：±50 ms（预约启播后 300 ms 才进入稳态统计）。
- 25 fps 视频输出 PTS 步长：不超过 40.1 ms；帧回调间隔：不超过 120 ms。
- 解码音频缓冲 PTS 缝隙：不超过 1 个 44.1 kHz 采样点加 0.005 ms 数值余量。
- preroll/停止时的无效音频区间单独记录；有效音频同时用源 host time 和媒体 PTS
  过滤，避免延迟 drain 污染下一场景。
- 连续/边界用例要求只有一次初始 seek 和一次预约启播，没有内部重新起播。
- 控制用例检查迟到定位、暂停不移动、恢复追赶、取消旧 seek、未来起点从零、
  原生自然结束位置和结束后不重开。
- 8 个分析器自测含故意丢帧、丢音频缓冲、错误时钟、额外 seek、缺场景等失败负例。

**这些指标不是扬声器测量。** 输出视频帧可用不等于实际屏幕扫描输出；
音频 tap 位于硬件输出前，时间戳连续不证明波形接缝无声学问题，
也不能证明没有听感上的吞字。没有测得多台真机出声偏差。

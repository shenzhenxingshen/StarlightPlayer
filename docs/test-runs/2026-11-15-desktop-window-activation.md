# 2026-11-15 电脑版后台窗口唤起修复

状态：实现已提交并推送为 `5ae16f8`，自动化检查、部分 macOS GUI 实测及 Windows 安装后 GUI 回归通过；macOS Dock/托盘、Windows 固定任务栏入口的实际点击验收未完成。四平台安装包构建成功，制品身份和下载站发布状态见[修订构建记录](2026-11-15-desktop-window-activation-release.md)，不能仅凭构建成功视为已发布。

## 问题与根因

用户报告：Windows 后台运行后再次打开快捷方式是否能恢复窗口；macOS 点击 Dock 或菜单栏图标不能直接恢复主界面。

源码确认：

1. 关闭窗口默认只 `hide`，原生 Host 继续运行，这是期望行为。
2. 原实现没有单实例唤起通信。再次直接启动 EXE/二进制会遇到已有的 `playback.lock`，无法通知旧进程打开窗口。锁已经防止两个 Host 并发写数据，不能把问题描述成“原实现必然同时播放两份声音”。
3. macOS 未处理 `RunEvent::Reopen`，遗漏 Dock/Finder 的重新打开入口。
4. 托盘仅有菜单事件，没有图标点击事件；原先只能选菜单中的“打开星光播放器”。

## 改动与不变约束

- 引入并优先注册 `tauri-plugin-single-instance`，锁文件固定 2.5.5；保留数据文件独占锁。
- 单实例回调、macOS Reopen、托盘点击、菜单打开、系统媒体 Raise 统一走 `shell::show`。
- 主线程内解除应用隐藏（macOS）、显示已有窗口、取消最小化、请求焦点；错误写入 stderr。
- 左键松开/Windows 左键双击打开；右键保留菜单；悬停及其他键不打开。Linux 使用菜单兜底。
- 不解释二次启动参数为播放请求，不新建窗口或 Host，不触发 `play/control`。
- 未修改共享业务核心、同步算法、N 遍判断、任务调度、音频或移动端代码。

参考依据为 Tauri 官方 Single Instance/System Tray 文档和锁定依赖源码，包括 Windows 前台授权及 macOS 托盘事件分发。未声称检查过 QQ/QQ 音乐源码或其所有平台行为。

## macOS 独立 QA 包与实测

为避免影响用户已安装并运行的应用，本次构建独立 QA 包：

- 名称：`Starlight Activation Test`
- bundle ID：`org.starlightplayer.desktop.activationtest`
- 临时配置通过命令行覆盖，未改产品 bundle ID 或用户配置。
- 产物：`apps/desktop/src-tauri/target/release/bundle/macos/Starlight Activation Test.app`。

第一次 Tauri release 构建与打包命令返回成功，但 rust-objcopy 报 `No space left on device`。随后的启动实际失败（`kLSExecutableIncorrectFormat`）；检查主程序只有 2,992 字节，`file` 识别为 `data`，不是可执行 Mach-O。这一次构建判为**不可用测试制品**。

已移除本次生成的损坏 QA `.app` 及两个损坏主程序产物（可重新构建）。后续磁盘可用空间回升至约 3.9 GiB 后重新构建成功，主程序约 12 MiB、确认为 Mach-O arm64，QA 包实际启动成功。不是直接复用损坏的旧产物。

第一段实测会话为北京时间 21:56:24 至 22:03:36，QA 进程 PID 30603；选择 A05、单曲循环、同步开启。结果如下：

| 操作 | 观察结果 |
| --- | --- |
| `⌘W` 关闭主窗口 | 界面工具报告 `noWindowsAvailable`，后台仍有 A05 进度日志 |
| 隐藏后再次直接执行 QA 主程序 | 第二进程快速以 0 退出；原主界面重新可访问，仍为 A05、同步播放，计数继续 |
| `⌘H` 后在访达打开同一 QA `.app` | 主界面重新可访问，焦点回到其 WebView，未重新启动播放任务 |

首段日志中只有 **1 次 `host-start`、1 次业务 `start`**，4 次自然结束、5 次曲目加载（初次及换遍），288 条进度记录；业务 generation 只随自然换遍增长，完成遍数最终为 3，没有因上述唤起新增暂停、停止或重新开始任务事件。首段从曲中同步加入，首个不完整周期不计数；播放时 UI 显示的当前第 4 遍与已完成 3 遍不是矛盾。没有音频回录，因此不能把日志连续性表述为已证明扬声器声音绝对无中断。

首次 `⌘Q` 后，界面工具重新查询 QA 应用时自动将其冷启动，形成第二个 `host-start`（22:03:46）。此时界面恢复 A05、已完成 3 遍、未自动播放；随后再次退出。**第二条 Host 启动是测试清理时的冷启动，不是唤起失败。** 分析日志必须按此边界区分会话。证据保留在忽略目录 `apps/desktop/test-results/window-activation-20261115.jsonl`。

## Windows 新增回归脚本

`apps/desktop/scripts/verify-windows-launch.ps1` 由已有安装验证流程调用；仅允许 `CI=true` 且安装路径位于 `RUNNER_TEMP`：

1. 新安装正常启动，无附带控制台，界面 IPC 初始化完成。
2. `WM_CLOSE` 后主窗口隐藏，原进程保持存活。
3. 隐藏后直接再次启动 EXE，第二进程在 15 秒内退出，原窗口恢复前台。
4. 在临时安装目录创建实际 `.lnk`，隐藏后从快捷方式重复启动。
5. 最小化后从快捷方式启动，取消最小化并恢复前台。
6. 已在前台时再次启动，仍保持同一主窗口。
7. 每次检查原 PID/窗口句柄、可见及最小化状态、前台 PID、配置文件哈希、日志中只有一次 `host-start`。

上述脚本已在 [CI run 43724645546](https://github.com/shenzhenxingshen/StarlightPlayer/actions/runs/43724645546) 的 Windows job `132843854392` 执行通过。安装对象是本轮生成的 NSIS 安装包，不是开发服务器或旧二进制。北京时间 2026-11-15 22:41:28 至 22:41:43 的关键结果：

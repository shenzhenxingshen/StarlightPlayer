## 2. 验证设计

共同的 `packages/program-core` 负责按整数 ticks 编译和定位流程，
Swift 的 JavaScriptCore 执行其编译产物。已用 `cmp` 核对两端构建出的核心 JS 完全一致。
原生播放控制仍由各自适配器实现，不宣称已完成统一的生产状态机。

桌面采用 EDL 将四份文件形成**单个虚拟媒体时间轴**：

```text
片头 42.280 s
  → 正文 73.760 s ×48
  → 特殊末遍 77.840 s
  → 片尾 76.772993197 s
```

51 个跨度，50 个内部接缝；总长 `164818149 / 44100 = 3737.372993197279 s`。
素材 revision：`6c551160e0e4-c078aaa5d999-cb3296034c05-c527baa8d2bb`。
素材身份及与原视频短 760 ms 的区别见 [iOS 原型记录第 3 节](2026-11-17-video-program-spike.md)。

首次加入或明确恢复时 seek，原生内部跨片段不发额外 seek。
迟到按同一发生实例起点追赶；暂停期间公共墙钟继续前进，不把跳过的遍次计为本机完成。
已知未来起点提前准备目标 0，通常中途加入提前 500 ms 准备。
主线程用单调时钟到期后发解除暂停命令；不是硬件精确预约输出。
过期准备重算、异步回调用 generation 取消；整套结束不从头重开。

## 4. 执行中遇到的问题及处理

1. 初期可见窗口测试提前触发关闭，只有首个或前两个边界的部分记录；
   没有完成标记，分析器拒绝通过。未确认外部关闭来源，不归咎于播放引擎。
   后续自动测试隐藏窗口、不抢键盘焦点，并增加关闭/终止日志，完成全部场景。
   初始 UUID 记录和 `2026-11-17T03-33-32-630Z-quick` 均保留为未完成结果。
2. `2026-11-17T03-34-31-974Z-quick` 完成 11 个场景，但旧分析器因自然结束前
   两个样本没有 `audio-pts` 而失败。核对 mpv 0.42 `player/command.c`：
   音频状态达到 EOF 后该属性返回 unavailable，可能早于整体 EOF。
   最终分析器只对最后 300 ms 内且距整体 EOF 不超过 350 ms 的空窗作有限排除，
   保留数量并新增正反例；不能因此说尾部声音已经得到完整验证。
   最终全接缝运行采用新分析器重新采集，不覆盖旧失败记录。
3. mpv 出现一条警告：末片声明时长和源时长都打印为 `76.772993` 秒，
   但浮点比较认为前者稍长。EDL 使用 12 位小数，容器与采样时长精度不同；
   上游 `demux/demux_edl.c` 对任何 `end_part > end_time` 都警告，没有容差。
   保留此警告；实测整体时长一致，不将警告当作已证明的音频截断。
4. 链接器警告本机 libmpv 构建目标 macOS 27.2 高于原型目标 27.0。
   此机确实运行成功，但不能推出可兼容 macOS 15、Intel 或任何其他电脑。
   发布前必须重建一致的依赖基线、内置动态库及完成签名/公证。
